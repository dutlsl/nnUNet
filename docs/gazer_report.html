2-4. 시연 목표 예산 분석 (최종 목표 기준)

시연 최종 목표: 단일 RTX 4090에서 T=8, 아이캠 2 스트림 각 120Hz 실시간 세그멘테이션 + 월드캠 60Hz 게이즈 매핑(CPU)이 병목 없이 처리. GPU 예산 = 1000 ms / (2 스트림 × 120 Hz) = 4.17 ms/스트림 프레임. 실험 서버 실측(1 스트림) 5.03 ms/프레임 → 스트림당 예산(4.17 ms)의 1.2배, 이미 1스트림도 초과. 2스트림 병렬 시 GPU 총 수요 = 2×5.03 = 10.07 ms/사이클, 사이클 예산(2×4.17 = 8.33 ms)의 1.2배 초과 (3090 기준, T=5 실측). 과거 실측 기록: FIFO 도입 전 T=3에서 1,000프레임 중 ~800프레임(80%)이 레이턴시 초과로 탈락 — 시연 환경이 속도 부족 상태였다는 직접 증거. 이 벤치는 인풋 1 스트림만 넣은 통제 실험이므로, 좋은 FPS 수치를 시연 환경의 절대 지표로 해석해선 안 된다.

2-5. 판정

가설 확인: 연산 병목은 Mamba3가 아니라 CNN. FLOPs 21.4:1, wall time의 61%는 CNN decoder (dec1/2/3 각각 55 GFLOP — 전체 forward의 1/3). Mamba3는 스트리밍 프레임당 +1.85 ms만 기여. 이 병목 측정은 annealing 상대의 크기를 정량화한 근거이며, 4단계의 annealing 대상은 bench 수치로 CNN 인코더·디코더 양쪽 (합계 291 GF, 전체 forward 333 GF의 87.2% — bottleneck 28 GF는 출력 폭이 Mamba3 입력이라 고정). 대상의 최종 선정은 RL 보상 게이트(4단계 Stage B)의 실측 하락 허용도가 판정 — 단계적 fade-out 후 agreement가 teacher−0.01 이상 유지되는 가장 가벼운 변종. 시연 예산은 스트림당 4.17 ms(2스트림 병렬 시 4.17 ms/사이클)인데, 풀 모델(5.03 ms/프레임)은 스트림당으로도 1.2배 초과 — 1스트림만으로도 3090 기준 이미 초과이므로 여유가 0에 가까움. 경량화는 시연 목표 달성을 위한 필수 경로. 4090의 실제 가속 계수는 미측정이므로 4090 풀 모델이 예산을 통과할 여지도 있으나, 이는 시연 환경 실측으로만 판정한다. 실험 서버 수치는 모듈별 상대 비율(인코더:mamba:디코더, 변종 간 개선 폭)만 유효하게 사용한다.

4. 경량화 + Annealing (실험 실행 중)

4-0. 목적 재확인 (10-27 사용자 정정 반영)

경량화의 목적은 학습 시간 절약이 아니라 인퍼런스 실시간성. 시연 환경 = RTX 4090 1장, 최종 목표 T=8에서 아이캠 2 스트림 × 120Hz + 월드캠 60Hz 게이즈 매핑(CPU) 병목 없음. 실험 서버(3090, 1 스트림) 수치는 상대 비율(모듈 기여도, 변종 간 개선 폭)만 유효하며, 시연 예산(4.17 ms/스트림 프레임) 충족 여부는 시연 환경 실측으로 판정. 실험 목적 = RL 보상 유지 전제 최대 경량화: val/agreement_teacher가 gazer_ep9(teacher)보다 −0.01 이내를 유지하면서 params/latency를 최대화(최소화)하는 변종 선정.

4-1. Annealing 대상: CNN 인코더 + 디코더 2×2 그리드 (사용자 정정 반영)

bench가 CNN = FLOPs 318 GF(T5)로 CNN 전체(decoder 216 GF 64.5% + 인코더 75 GF 24.5% + bottleneck 28 GF 8.9%)가 병목 확인. 2단계 정정 (10-27): annealing 대상은 연산 병목 위치가 아니라, 단계적 fade-out 후 성능 유지 또는 합리적 하락을 RL+SAM3 튜닝으로 커버 가능한 연산량이 큰 모듈 — bench 수치로 CNN 인코더·디코더 양쪽이 대상(합계 291 GF, forward의 87.2% — bottleneck 28 GF는 출력 폭이 Mamba3 입력이라 고정). 구조적 제약: bottleneck 출력 폭 (base×8=256)은 Mamba3 temporal 입력으로, 학습된 Mamba3 가중치 인수를 위해 고정. encoder 폭을 줄이면 bottleneck 입력 폭만 바뀌므로 (신규 초기화 → 학습 대상), enc1/2/3만 좁힐 수 있고, 인코더 skip 폭과 디코더 폭 차이는 1×1 skip adapter가 브리징.

4-2. 실행 방법: Stage A warm-start 체인 → Stage B RL 보상 게이트

Stage A (SAM3-free annealed distillation, warm-start 체인 = 단계적 capacity fade-out): 체인 순서 e32d16 → e32d8 → e16d16 → e16d8. 각 변종은 이전 변종의 best checkpoint에서 shape-aware 로드(첫 변종은 gazer_ep9) → "점차 페이드아웃"을 실행 가능한 warm-start 체인으로 구현. 각 변종 trainable: decoder stages(+skip adapter, 폭 차이 시) / encoder stages + bottleneck (enc 폭 변화 시). 손실 = KL(p_s‖p_t) + α_tv(epoch)·TV(logits_s) (p_t = 동결된 gazer_ep9 포워드가 같은 GPU에서 산출, α_tv: 0.001→0.05 annealing). SAM3를 쓰지 않는 이유: 인플라이트 GRPO가 118GB train landscape를 RAM에 두고 있고, 251GB RAM에 두 개의 landscape를 둘 수 없기 때문. 진행 지표 = val에서 dice(student softmax, policy softmax).

Stage B (--gate, RL 보상 게이트): val 전용 SAM3 landscape (~16,800 프레임, ~27GB RAM, ~1.5–2h)를 1회 빌드해 동일 landscape·동일 지표로 gazer_ep9와 각 student_e*{dec}_best.pth를 재측정. 통과 조건 delta = student − teacher ≥ −0.01 — 통과 변종 중 params 최소를 선정(= "RL 보상이 유지되는 가장 가벼운 변종"). 이것이 2단계·3단계의 보상 정의(teacher-likelihood)를 4단계의 검증으로 직접 연결하는 인과 고리.

4-3. 실행 상태 (10-27 17:10 KST)

4-5. 수용 기준 (시연 목표와 연결)

  2. 시연 4090 실측: T=8, 아이캠 2 스트림 × 120Hz (GPU 4.17 ms/스트림 프레임 예산) + 월드캠 60Hz 게이즈 매핑(CPU) 병목 없음 — 실험 서버 수치는 이 기준의 대체가 아님
