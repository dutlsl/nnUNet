02 / 13 OVERVIEW

프로젝트 개요

이 포크는? (upstream 기반)

  • Pupil Labs Pupil: 오픈소스 아이트래킹 스택 (eye/world 프로세스 + ZMQ IPC + 플러그인 아키텍처)
  • 이 포크의 핵심 목표: 기존 2D C++ 엣지 기반 검출기 외에 신경망 동공 분할기를 병행 운영

추가된 3가지 동공 검출 방법

  • Mamba-3 (Vivim): 시계열 SSM (T=7) — 실시간 동적 윈도우 추론
  • RITnet: DenseNet2D 단일 프레임 분할 (기존 pretrained)
  • 2D C++: upstream C++ 엣지 기반 검출기 (베이스라인)

07 / 13 ISSUES ①

정확성(Bug) 발견 사항 우선순위 P0 — 동작을 틀리게 하는 문제

shadowed _empty_datum 중요

  • 동일 클래스에서 2번 정의 (:302 vs :580) — 후자가 섀도잉
  • 실제 사용 중인 버전은 method 키 미설정 → 다운스트림 필터·로그가 method 기대 datum에 대해 깨짐

T=5 / T=7 기본값 불일치 중요

  • __init__ 기본값 "Mamba3 (T=7)" vs detect() fallback "Mamba3 (T=5)" (T=5 모델 미로드)
  • _vivim_queues는 key=7만 존재 → T≠7 요청 시 KeyError (UI 제한으로 가려져 있음)

잔여·무효 코드

  • accuracy_visualizer의 0.2→2.0s 재시도 루프는 매칭 함수가 내부적으로 동일 래더를 실행하므로 항상 같은 결과를 반환 — 무효 로직
  • _detect_temporal_unet/_detect_nnunet_2d는 존재하지 않는 인스턴스 속성 참조
  • 미사용 import 다수 (fit_ellipse, deepvog, edgaze 등)

에러 처리 & 검증

  • GazerBase.__init__의 blanket except — 어떤 프로그래밍 오류든 "Calibration Failed!"로 변환, traceback는 DEBUG로만 출력
  • 차원 검증에 assert 사용 (gazer_2d.py:146-157) — -O 모드에서 제거됨 → AssertionError가 예기치 못한 경로로 유입
  • Ellipsis를 control-flow sentinel로 사용 — 가독성 ↓
  • get_init_dict가 active_model·flip flag 미영속 → 세션 복원 시 설정 손실
08 / 13 ISSUES ②

보안 & portability 환경 의존 리스크

시큐리티

  • torch.load(weights_only=False) ×3 (Mamba3, RITnet ×2) — 로컬 체크포인트라도 임의 pickle 실행 위험. weights_only=True + state-dict만 로드 권장
  • strict=False 로딩 → 키 불일치 시 무음 실패 가능 (실제로 backbone. 프리픽스 strip 로직이 존재)

hardcoded 개발자 경로

  • NNUNET_DIR = ~/PycharmProjects/nnUNet + sys.path 인젝션 (detector_2d_plugin.py:62-68) — 다른 머신에서 즉시 실행 불가
  • env var 또는 package-relative 경로로 대체 필요

방어적 monkey-patch

  • import 시 torch.float4_e2m1fn_x2/float8_e8m0fnu 가짜 속성 주입
  • sys.modules["numpy._core"] shim — numpy/torch 버전 갱신 시 깨짐 지점
  • main.py의 torch.load 전역 패치 — 모듈 경계 훼손

레포 위생

  • 루트에 미트래킹 ~20MB .pth 2개 + vivim/ (untracked) — 실수로 커밋되면 레포 팽창
  • 미커밋 문서·설문 2개, __pycache__에 CPython 3.7–3.10 바이트코드 혼재 (다중 인터프리터 개발 환경)
  • 리뷰 대상 자체가 커밋 ≠ 디스크 상태 (detector_2d_plugin.py -305줄) — 발표 기준선 명시 필요
09 / 13 ISSUES ③

동시성 & 견고성

로그 파서 스레드 (HEAD 기준) 워킹 트리에서 제거됨

  • notification마다 데몬 스레드 spawn, time.sleep(0.5) 타이밍 가정으로 메인 프로세스가 쓰고 있는 같은 로그 파일을 읽음 → 읽기/쓰기 레이스
  • 클로저가 self·active_model을 타스레드에서 참조 — 플러그인 상태 무결성 리스크
  • 워킹 트리의 SessionLogTee 방향은 올바르나 except Exception: pass로 디스크 오류·쓰기 실패가 무음 처리

참고 사례: Hybrid DVS 플러그인

  • threading.Lock + Event + bounded Queue + multiprocessing spawn 컨텍스트 — 이 영역에서 가장 잘 설계된 코드
  • 벤치마크 수치는 우수하나(하단 슬라이드) 결과 전달 경로가 병목

기타

  • 실시간 매처의 recently_estimated_framerate 변수는 실은 period(s/frame) — 명명 반전 hazard (matching.py:21)
  • map_batch 등 데드 API, f-string에 플래시홀더 없는 f"calibration.successful" 등 미세 smell 다수
  • batch 매칭: threshold 5단계마다 모든 ref에 대해 nearest-neighbor 재계산 → 최대 5배 중복 계산 (인덱스는 threshold와 무관 — 단일 패스 + 스윕으로 최적화 가능)
